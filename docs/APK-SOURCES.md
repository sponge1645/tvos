# Источники сторонних APK

`AppDownloads` обслуживает только «Настройки → Приложения». Обновление самого лаунчера выполняет `SelfUpdate`.

## Политика доверия

- Первая установка использует конкретный проверенный файл: закреплены его URL, SHA-256 и сертификат подписи.
- AirPlay, TizenTube и Lampa после первой установки могут получать новые релизы из прежнего GitHub-источника. Проверяются закреплённый сертификат, точное совпадение текущих подписантов установленной копии, имя пакета и Android versionCode. Серверные версии не заменяют проверку самого APK.
- Apple Music, INCY и Seena используют фиксированные сборки и SHA-256 при каждой загрузке. Подмена файла по прежней ссылке будет отклонена. Новая сборка требует обновления каталога после проверки.
- KinoPub разрешён из выбранного пользователем зеркала `kotlinbestuser/apk`. Первая установка использует файл 2.19 из конкретного коммита с закреплёнными SHA-256 и сертификатом. Последующие версии выбираются из зеркала и должны совпадать с закреплённым сертификатом и подписью установленной копии. Это явно принятая исходная сборка, а не независимое подтверждение личности издателя.
- Ротация ключей автоматически не принимается. Дополнительный подписант также считается изменением набора подписей.
- APK публикуется для Android-установщика только после проверок. Временный файл удаляется при ошибке/отмене; закрытие экрана отменяет загрузку. Отмена кооперативная, сетевое чтение ограничено таймаутом.

Подпись и хеш закрепляют идентичность выбранной сборки. Они не являются анализом её поведения или гарантией отсутствия вредоносного кода. Базовые источники сохранены из прежнего каталога; Apple Music — сторонняя адаптация, а не сборка, подписанная Apple.

Архитектуры проверены по содержимому `lib/` APK: AirPlay содержит ARM32/ARM64/x86_64; Apple Music, Lampa и KinoPub — ARM32/ARM64/x86/x86_64; INCY — ARM32/ARM64; Seena — только ARM32. TizenTube распространяется отдельными ARM32 и ARM64 файлами, выбор выполняется по `Build.SUPPORTED_ABIS`: ARM32 при поддержке, иначе ARM64. Этот приоритет действует и для первой установки, и для обновлений. При выборе release assets других приложений совместимый отдельный 32-битный APK также предпочтительнее 64-битного или универсального. Универсальные закреплённые APK скачиваются целиком.

Полные URL, SHA-256 файлов и SHA-256 DER-сертификатов находятся рядом в `AppDownloadCatalog.java`. Apple Music использует сертификат с `CN=Android Debug`, поэтому проверка её точного файла обязательна. Название Subject сертификата само по себе не устанавливает доверие.

## Совместимость чтения сертификатов на ТВ

Запрашиваются оба флага `GET_SIGNING_CERTIFICATES | GET_SIGNATURES`. Основной источник — текущий набор `SigningInfo.getApkContentsSigners()`. Если прошивка не вернула текущие сертификаты через `SigningInfo`, используется `PackageInfo.signatures` с теми же проверками точного набора сертификатов и закреплённого SHA-256. При наличии текущих сертификатов в `SigningInfo` устаревшее поле не может переопределить результат. Отсутствие сертификатов теперь отличается от несовпадения отпечатка отдельной ошибкой. Закреплённые отпечатки всех восьми APK повторно проверены через `apksigner`; они не изменились.

## Как обновлять закреплённые сборки

1. Скачать APK из указанного источника. Не брать сертификат из нового файла и автоматически считать его доверенным.
2. Проверить криптографическую подпись APK, имя пакета, минимальную версию Android и versionCode. Сопоставить сертификат с прежним закреплённым ключом; изменение ключа требует отдельного подтверждения происхождения.
3. Проверить SHA-256 файла, а для GitHub — также digest release asset. Для ARM64 TizenTube проверять отдельный хеш; подпись у двух проверенных вариантов одинакова.
4. Обновить запись `AppDownloadCatalog`: URL/хеш, reviewedVersionCode и документацию. При смене URL `latest` старый хеш нельзя удалять ради обхода ошибки.
5. Запустить `tests/test_app_downloads.py`, все остальные JVM-тесты и Android-сборку; проверить установку на устройстве.

Источник без явно принятого исходного APK и закреплённого сертификата по-прежнему не допускается к первой установке.

## Структура кода

- `AppDownloads`: окно загрузки, отмена, жизненный цикл и запуск Android-установщика.
- `AppDownloadCatalog`: источники, закреплённые сборки, архитектура и выбор релиза.
- `ApkTransfer`: потоковая загрузка, лимиты, HTTPS-переадресации, контрольная сумма и очистка частичных файлов.
- `ApkTrust`: идентичность APK, закреплённый сертификат и подпись установленной копии.
- `AppVersions`: безопасное сравнение числовых версий имён файлов, включая `2.9 < 2.19`.
