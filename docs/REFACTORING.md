# Постепенное разделение кода tvOS 1.1

Основное ограничение: простой код, прежний пиксельный дизайн и функциональность.
Разделение крупных `HomeView`, `SettingsActivity`, `HomeApps`, `Recs` выполняется
небольшими проверяемыми шагами. Оно само по себе не является доказательством роста FPS.
Уже выполненные оптимизации постеров, дискового кеша и фоновой загрузки сохраняются.

## Выполнено в dev.2

- `AppBranding`: единый справочник цветов, режимов окрашивания, ресурсов и оптических
  поправок логотипов. Презентационный alias `watch.kino.mod` использует профиль
  `watch.kino`. Он не заменяет пакеты в Intent, списках установленных приложений,
  пользовательских настройках, каталоге загрузок или проверке подписи APK.
- `DockLogoRenderer`: подготовка обычного/тёмного варианта логотипа, дробные координаты,
  фильтрация при уменьшении и жизненный цикл кеша. `HomeView` передаёт только
  приложение, геометрию и параметры фокуса; прежние точки очистки кеша сохранены.
- Во время анимации логотип повторно не масштабируется; кеш не строит строку с ID
  исходного bitmap на каждом кадре. Смена исходника заменяет запись, кеш ограничен
  двумя вариантами на приложение. Bitmap исходного приложения не освобождается
  отрисовщиком; старые готовые изображения не перерабатываются вручную, пока их
  может использовать отрисовка.

Проверки: 18 исходных профилей оформления, совпадение двух вариантов KinoPub в
Dock и All Apps, самостоятельные пакеты запуска, кеш, цвета, режимы окрашивания,
нечётные/чётные размеры, переход через старый порог округления, пружинные анимации,
смена изображения/размеров/оптических параметров и освобождение промежуточных bitmap.

## Следующие отдельные шаги

1. Поиск: вынести состояние запроса, задержку запуска, отмену и проверку актуальности
   результата. Сначала сохранить маршруты фокуса и нынешний жизненный цикл; их
   существующие тесты должны оставаться зелёными.
2. Рулетка: отдельно вынести выбор, отмену и отложенные действия. Кнопки, отрисовку,
   фокус и текущую работу Back переносить без изменения поведения.
3. Подготовка изображений и извлечение логотипов из `HomeApps`: отделить CPU-обработку
   от обнаружения/запуска приложений, сохранив ограничения памяти и работу вне UI.
4. Далее разделять данные экранов настроек и задачи `Recs` небольшими этапами,
   не создавая универсальный фреймворк ради самого разделения.

После каждого шага: профильные проверки, все регрессии, сборка APK, затем визуальная
проверка пользователем. Геометрия, фокус и анимации меняются только при отдельной
подтверждённой ошибке или задаче на дизайн. Результат по CPU/RAM/FPS проверяется
измерениями на телевизоре, а не размером Java-файла.
