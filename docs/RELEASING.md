# Подготовка и публикация tvOS

Кандидат: **1.1.2 (1B201)**, ветка `1.1.2`. Публикация — отдельное действие.

## Проверка кандидата

1. Дождаться зелёного CI именно для итогового коммита: JVM, строгая компиляция APK,
   ресурсы, DEX и тестовая подпись. Push в `1.1.2` запускает этот workflow.
2. На ТВ проверить смену Подборка/tvOS-вид, оба вида карточек, фокус после «Назад»,
   четыре состояния погоды, поиск, аватар, сон/возврат и работу без сети.
3. Убедиться, что локально восстановлены config.properties и signing.local.json.
   CI APK использует одноразовый ключ и не предназначен для выпуска.

## Сборка

На локальном компьютере с Android SDK и рабочей подписью:

```sh
./release.sh 1.1.2
```

Скрипт сохраняет текущий versionCode при том же versionName; при повышении версии
увеличивает versionCode. SoftwareBuild.SEQUENCE задаёт явный номер сборки.
build.sh добавляет assets/build-info.json, подписывает APK, проверяет внешние ресурсы
и вызывает prepare-release.py с aapt2 из той же версии build-tools.

Перед формированием release/update.json проверяются идентичность build-info исходникам
и фактические пакет/versionCode/versionName скомпилированного APK. Старый APK
без build-info нужно пересобрать. В update.json сохраняются размер, SHA-256 и номер сборки.

## Публикация после проверки

```sh
python3 tools/publish-release.py
```

Создаёт черновик GitHub Release. После отдельного решения о публикации:

```sh
python3 tools/publish-release.py --publish
```

GitHub Latest содержит стабильный APK; его legacy-манифест направляет старые версии
на мост 1.0.4. Для версий 1.0.4+ используется канал ota-v1.
Ключи, конфигурацию и CI APK не публиковать. Описание кандидата: [releases/1.1.2.md](releases/1.1.2.md).
