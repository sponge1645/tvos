# Выпуски tvOS

Репозиторий: https://github.com/sponge1645/tvos

## Первый выпуск 1.0

1. Примените эти исходники к своему рабочему проекту. Сохраните текущие config.properties и freemytv.keystore.
2. Выполните `./build.sh && adb install -r tvOS.apk`.
3. Откройте https://github.com/sponge1645/tvos/releases/new.
4. Создайте тег `v1.0`, название `tvOS 1.0`, ветка `main`.
5. Прикрепите **оба файла**: `release/tvOS.apk` и `release/update.json`.
6. Нажмите Publish release. Не отмечайте pre-release. Выпуск должен быть Latest.

До первого выпуска проверка покажет, что выпуск или файл обновления ещё не опубликован.
После публикации 1.0 лаунчер версии 1.0 должен показать, что он актуален.

## Следующая версия

Внесите изменения в код, затем выполните `./release.sh 1.0.1`.
Скрипт увеличит Android versionCode, соберёт подписанный APK и подготовит два файла в release/.
Сохраните изменения исходников (включая новую версию в манифесте) в репозитории до создания выпуска.
Создайте выпуск `v1.0.1` и прикрепите новые `tvOS.apk` и `update.json` из одной сборки.
Не заменяйте файлы уже опубликованного выпуска; используйте новую версию и тег.

Если GitHub CLI установлен и вы вошли в свой аккаунт, после загрузки исходников можно опубликовать:

```bash
gh release create v1.0.1 release/tvOS.apk release/update.json --repo sponge1645/tvos --title 'tvOS 1.0.1' --notes 'Описание изменений' --latest
```

## Как работает обновление

- Кнопка «Обновление ПО» проверяет update.json последнего стабильного выпуска.
- «Загрузить и установить» скачивает APK из указанного тега и проверяет размер, SHA-256, пакет io.tvos и versionCode/versionName. Метаданные пакета читаются без запроса сертификатов; доступные текущие сертификаты сравниваются отдельно. Явное несовпадение подписей блокируется. Если прошивка не возвращает сертификаты, окончательная проверка подписи и возможности обновления выполняется штатным установщиком Android, который обязателен для установки.
- Затем открывается системный установщик Android. При необходимости разрешите tvOS установку из этого источника и выберите «Установить» повторно.
- Автоматическое обновление проверяет выпуск не чаще раза в сутки, пока главный экран/настройки активны, и скачивает новую версию. Установка требует подтверждения на ТВ.
- Сервер/VPS, GitHub-токен в приложении и отдельное приложение GitHub на телевизоре не нужны.
- Ключ подписи не меняйте. Не отключайте системный установщик: именно Android окончательно проверяет подпись APK перед заменой приложения.

## Что не публиковать

freemytv.keystore, config.properties, out/, резервные копии и личные токены.
CI проверяет сборку с одноразовым ключом и не выпускает APK для пользователей.

## Нумерация версий

Исправления и небольшие улучшения: 1.0.1, 1.0.2 и далее.
Крупные обновления с новыми функциями: 1.1, 1.2 и далее.
Android versionCode увеличивается с каждым опубликованным обновлением независимо от видимого формата версии.

## Проверка нового выпуска при готовом APK

Ручная проверка всегда перечитывает Latest с запретом сетевого кеширования и уникальным параметром запроса. Готовый APK переиспользуется только при совпадении тега, версии, SHA-256 и размера. Автоматическая проверка сохраняет суточный интервал, включая случай уже загруженного APK.

## Ветки и актуальная версия

После проверки объединять рабочую ветку в main через squash merge. main содержит актуальную версию выпуска. Сборку и тег связывать с конкретным итоговым коммитом main, а не с подвижной рабочей веткой.

## Согласованное переиздание 1.0.2

По явному решению владельца 1.0.2 переиздаётся с исправленным OTA-загрузчиком: versionName остаётся 1.0.2, versionCode увеличен с 4 до 5. Это исключение из обычного порядка новых версий выше.

Собрать release/tvOS.apk и release/update.json одним запуском release.sh на Mac с прежним ключом. После успешной сборки временно перевести выпуск v1.0.2 в черновик, переместить его тег на новый коммит main, заменить оба файла и описание, затем снова опубликовать как Latest. До загрузки обоих файлов выпуск должен оставаться черновиком.

Не публиковать проверочный APK с одноразовым ключом. Подтверждённые тестовые переходы 1.0 и 1.0.1 → 1.0.2 проверяют тот же код загрузчика, который включён в переиздание. Уже установленному старому клиенту это не меняет код проверки автоматически: при отказе его OTA исправленную сборку устанавливают однократно поверх через ADB без удаления данных.
